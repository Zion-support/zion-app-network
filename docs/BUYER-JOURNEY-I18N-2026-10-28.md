## Recommended journey

1. Begin with the [free AI Discovery](https://ziontechgroup.com/discovery/) to scope a specific workflow; never present heuristic ROI as measured savings.
2. Compare the [Apps Network](https://ziontechgroup.com/zion-app-network/), [service plans](https://ziontechgroup.com/en/plans/) and [case studies](https://ziontechgroup.com/cases/).
3. Evaluate the [insurance evidence workbench](https://ziontechgroup.com/apps/insurance-evidence-workbench.html) for supplier evidence preparation, not insurance approval.
4. For field-service work, verify named engineer, city coverage, all-in price, insurance, access, scope, times and client written PO before any supplier commitment. Zion's separate release is mandatory.
5. Return from each app/guide to the network index and free Discovery; cross-link a relevant sibling app rather than linking every app indiscriminately.

## Publication and translation acceptance gates

- Five languages: EN, PT, ES, FR, DE. Do not mix navigation/body language or ship placeholder translated fragments.
- Every published localized page must have accessible language switcher, a translated H1/meta title/description, a working primary CTA, network backlink and Discovery link.
- Check valid targets, locale-specific canonical/hreflang, keyboard focus, mobile layout and no horizontal overflow.
- Keep terminology for cost, SLA, pilot, approval, security and human oversight consistent across languages. No unsupported promises of autonomous dispatch, guaranteed ROI or verified service reach.
- Run repository contract tests and a real HTTP smoke test of each deployed URL; record exact tested URL, timestamp, HTTP response, language and click-path. A GitHub commit or passing unit test alone does not establish a live deploy.
- Preserve existing features, link paths and existing content. Use reviewed PRs for behavioral code changes, especially where CI tests fail.
