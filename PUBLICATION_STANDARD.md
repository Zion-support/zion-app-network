# Zion App Network — publication standard

## Shared pattern

1. Use the existing /assets/css/site.css, semantic main content, a skip link, visible keyboard focus, readable contrast and responsive cards.
2. Include home, network, related apps, source repository and always-free Discovery navigation. Link peers reciprocally; do not attempt an unreadable all-to-all link list.
3. Publish complete English, Portuguese, Spanish, French and German variants when supported by the source. Keep product names unchanged but translate descriptions, form labels, instructions, status messages, safety/privacy text and CTAs.
4. Add a canonical URL, reciprocal hreflang links, x-default and an actual language selector. A language switch must preserve the selected app or guide.
5. Label the implemented capability precisely: functioning local tool, prototype, documented concept or verified production integration. HTTP 200 alone is not a functionality test.
6. Discovery is always online and free. Generate the report before attempting email. Send the same report to commercial@ziontechgroup.com and the validated client email; retain honest pending/accepted/error/timeout states, duplicate protection, copy/download and manual fallback. Provider acceptance is not proof of receipt.
7. Never insert user input with innerHTML. Prefer textContent, validate fields, limit lengths, do not embed secrets or unneeded recipients, and do not store/share customer records by default.
8. Before publishing: validate translated content completeness, navigation, form behavior, script syntax, export behavior and duplicate section prevention. After publishing: verify real HTTP status AND release markers, assets and reciprocal localized links.
